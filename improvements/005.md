# IMP-005 · 受管架构文档章节编号：守卫只校验「连续」，且约定从 1 起（去掉硬编码的 0 起点）

## 背景

IMP-001 提出的真实需求是「章节编号 / 层级必须保持**连贯**；禁止插入不编号的浮动小节打断既有 `§0–§N` 序列」。该需求只包含两条：① **不跳号**；② **不允许未编号的顶层小节**。**没有任何一条要求「必须从 0 起」**——`§0–§N` 只是当时文档样貌的描述（彼时各篇首节恰好都写作 `## 0. 背景与…`）。

落地为 `scripts/structure_lint.py`（根项目 history #55）时，实现写成：

```python
expected = list(range(0, nums[-1] + 1))   # 硬编码 0 为起点
if nums != expected:
    ... "缺 %s（必须从 0 连续）"
```

即把「观察到的起点 0」当成了「强制的起点」。后果有二：

1. **误判**：一篇编号 `1、2、3…N`、完全连贯、零跳号的文档，会被判违规，理由是「缺 0」。守卫把无关约束强加给了文档。
2. **倒逼结构臃肿**：为满足守卫，写文档的人被迫额外造一个 `## 0.` 前言章节（否则 lint 不过）。采纳方 `euston-daily-collect` 的 `architecture/002.md` 即为此被迫添加 `## 0.`，用户明确反馈该结构造成负担与过载。

## 改进点

1. **守卫语义只保留「连续」**：起点由文档自身的首个顶层章节号决定，不再硬编码 0。
   ```python
   expected = list(range(nums[0], nums[-1] + 1))
   ```
   提示语同步改为「序号必须连续（不跳号）」，去掉「必须从 0 连续」的表述。
2. **文档约定改为从 1 起**：受管架构文档的顶层章节统一以 **§1** 起始（§1、§2 … §N）。背景 / 前言 / 关联类内容并入 §1（或作为 §1 的前言段落），不再单列 §0。
3. **存量文档迁移**：现有 `architecture/001–008.md` 及采纳方同类文档需重编号（§0→§1、§1→§2 …），并同步修正正文中的 `§N` / `§N.M` 交叉引用。根项目共约 102 处引用（其中 `003.md` 53 处），必须脚本化处理并逐篇 `structure_lint` 验证。
4. **规范条文同步**：`references/workflow.md` 守卫条款中的「打断既有 `§0–§N` 序列」改为「打断既有编号序列」，并新增「顶层章节从 1 起编号」的约定。

## 实现要点
