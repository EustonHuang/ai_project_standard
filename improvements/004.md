# IMP-004 · 受管文件夹文件堆积导致的浏览过载：以「最新指针 + TOC 优先」替代扁平列表

## 背景
`history/`、`questions/`、`improvements/`、`issues/`、`architecture/` 均为单目录扁平存储，文件数随时间无上限增长。当用户想看「最新一条记录」时，IDE 默认打开的是整个文件夹的扁平文件列表（数百个 `NNN.json` / `NNN.md`），必须在一长串命名规整、内容无法一眼区分的文件里翻找，浏览成本高、易产生淹没感。索引（`*_index.json`）与 TOC（`*_TOC.md`）虽已生成，但用户日常仍以「打开文件夹」为入口，未充分利用聚合视图。

## 改进点
1. **每类新增稳定「最新指针」**：`append_history.py` 在落盘每条记录后，于对应类别根写一份派生指针文件——`history/latest.json`、`questions/latest.md`、`improvements/latest.md`、`issues/latest/`——始终指向该类别当前最新一条。用户只读一个固定路径即可拿到最新记录，无需遍历文件夹。指针为纯派生缓存，不进审计、不计入历史事件覆盖。
2. **TOC 作为用户面浏览器并置顶最新**：在现有 `*_TOC.md` 顶部固定「最新」区块（含标题 + 直链到最新文件），并约定「看最新 → 开 TOC 或 latest 指针，不开文件夹」。TOC 既有的「仅显示最近 N 条」窗口已天然限制列表长度，置顶最新后可彻底替代文件夹浏览。
3. **长期可选：旧记录按年份分片**：当单目录文件数超过阈值（如 200），将旧记录移入 `YYYY/` 子目录（如 `history/2025/001.json`），保持扁平目录短小。属后续版本的可选项，不破坏现有编号与索引语义即可引入。

## 实现要点
- `append_history.py`：`cmd_append_*` 收尾时，除更新索引 / 重生成 TOC 外，额外写出 `<cat>/latest.<ext>`（指向 `max_id` 对应文件）；`set-implemented` 同理刷新 `architecture/latest.md`。
- `latest.*` 加入 `.turngateignore`（派生缓存，豁免记账与历史覆盖强检），并在 `gen-toc` / `rebuild-index` 时一并刷新。
- `*_TOC.md` 模板在列表前插入「## 最新」区块，渲染最新一条的 id / 标题 / 直链。
- 年份分片（若采纳）：`migrate` 提供 `--shard-by-year` 选项，仅重排物理路径，索引中的 `file` 字段同步改写，编号不变。

## 范围界定
- **必须**：latest 指针（history / questions / improvements / issues / architecture）+ TOC 置顶最新。
- **可选（后续版本）**：旧记录年份分片。
- 不改动既有「一文件一事件」的追加语义与编号规则；指针与分片均为派生 / 重排，不改变记录正文。
