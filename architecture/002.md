## 2. 命名与索引约定

- **零填充 3 位 ID**：`001`–`999`；超过 `999` 时给低于 `1000` 的文件补 0 转 4 位（如 `0999`→`0999`, `1000`），文件名以 `event_id` 为整数权威序，宽度仅美观。
- **每类（history/questions/issues/architecture）都有 `*_index.json`，且一律放在 `<plan>/` 根（与类目文件夹同级，绝不进类目文件夹）**，记录：
  - `history_index.json` / `questions_index.json` / `issues_index.json`：`max_id`（或 `max_issue_id`）+ 每文件简要 + `revision`（每次成功提交 +1，或存内容哈希作版本号）。
  - `architecture_index.json`：`implemented_version`（当前已落地版本）、`latest_version`（最新目标版本）、各版本简要。两者一致=已 execute，不一致=待执行。
- **每类可配 `*_meta.json`，同样放在 `<plan>/` 根**，存放 plan 级元信息。（注：`*_meta.json` 已在 architecture 003 删除，plan 级字段见 `architecture_index.json`，非结构化说明见各 `*_index.json.notes`。）
- **简要信息零额外成本**：直接复用事件内已有字段 `operation.change_summary` 与 `actor.type` 进索引，不额外调用 AI 总结。

## 3. 脚本重写（`scripts/append_history.py`）

命令：
- `init --plan DIR [--meta ...]`：建 `architecture/ history/ questions/ issues/` 目录 + 在 `<plan>/` 根建空索引 + meta。
- `append --plan DIR --event E.json [--kind history|questions|issue]`：见下提交流程。
- `show --plan DIR`：仅读对应 `<plan>/` 根的 `*_index.json` 打印简要（**不扫全量**）。
- `audit --plan DIR`：校验各文件夹与 `<plan>/` 根索引一致性（缺口/多余/碰撞、index 与文件不符），输出 desync 报告，可触发 issues。
- `rebuild-index --plan DIR`：从 `*/` 下文件重算 `<plan>/` 根的索引（索引可重建，符合 Q5 思想）。
- `migrate --plan DIR`：一次性把旧 `history.json`（数组）+ 旧 `questions.md` 迁到新布局（见 §5）。
- `recover --issue 001`：根因修复后，把 `issues/001/assets/intended_*.json` 正式写入并重放。

**append 提交流程（互斥锁 + 版本守卫）：**
1. 读 `<plan>/` 根的 `*_index.json` → 记 `revision`，取 `max_id`。
2. `next_id = max_id + 1`，文件名 `zeroed(next_id)+".json"/.md"`。
3. 在 `issues/<staging>/assets/`（或 `.tmp/`）写**意图内容**（event_id/recorded_at 等由脚本补）。
4. 获取锁（原子 `mkdir .lock`，写 PID+TTL）；锁被占 → 退避重试 ≤ N 次；超次 → 建 issue（`lock-timeout`）中止。
5. 持锁下重读索引：若 `revision` != 步骤1 记录值 → 陈旧读（他人已提交）→ 释放锁，建 issue（`stale-read`，含意图内容）中止。
6. 检查目标文件是否已存在 → 碰撞 → 释放锁，建 issue（`collision`，含意图内容 + 现有文件副本）中止。
7. 全通过 → 落盘目标文件，更新 `<plan>/` 根的索引（`max_id`、`revision+1`、追加简要），释放锁。
8. **锁撤销通知（防死锁）**：若持锁进程超过 TTL，后来者可抢占锁并在锁文件标记 `revoked`；原进程提交前复核所有权，若已非 owner → 中止并建 issue（`lock-revoked`），此时等待重试或进 issues。

## 4. issues 兜底

- 目录：`issues/{zeroed_issue_num}/description.json` + `assets/`（位于 `issues/` 类目文件夹内）。
- `description.json` 字段：`issue_id`、`event_type`（如 `history_append`/`questions_append`/`index_desync`/`lock_revoked`/`lock-timeout`）、`description`、`detected_at`、`intended_action`（目标路径、拟用 id、拟写 max_id、所读 `revision`）、`assets_refs`、`status: open|resolved`。
- `assets/` 含：`intended_<target>.json`（本想写入的逐字内容）、`existing_<target>.json`（若碰撞，现有冲突文件副本）、`index_snapshot.json`（检测时刻索引副本）。
- 修复后由 `recover` 重放 `intended_*.json`。
- `issues_index.json` + `issues_meta.json` 同构其他类目（但放在 `<plan>/` 根，不进 `issues/`）。
