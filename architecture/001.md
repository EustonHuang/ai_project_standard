# Plan History Recorder — 设计计划（Skill · 修订版）

> 本文件是这个 skill 本身的设计说明（也作为该 skill 的 `plan.md`）。
> 配套实现位于同目录下的 `SKILL.md`、`references/`、`scripts/`、`assets/`。
> 本 skill 的目标：为**任意** `plan.md` 维护一份「可溯源、只增不改」的修订历史。

---

## 0. 修订摘要（相对初版）

初版把 `history.json` 设计成 `{schema_version, plan_id, plan_title, created_at, events:[...]}` 的**包裹对象**。这是缺陷：把"文件级 `schema_version`"和 event 混在一起，制造了"schema 演进 vs 只增不改"的伪冲突。

**修订决定（用户拍板）：**
1. `history.json` 改为**纯数组** `[event, event, ...]`，不再有外层包裹对象（即用户所指的 `[{},{}]` 形式）。
2. `schema_version` 是 **event 级** 的，放进**每个 event 内部**；不存在文件级 `schema_version`。
3. 顶层四个元信息字段（`schema_version` / `plan_id` / `plan_title` / `created_at`）**统统去掉**；若需要 plan 级元信息，单独建 `history_meta.json`。
4. `timestamp` 字段去掉（沿用 ①），时间以 `recorded_at`（脚本写入真实时钟）为准。

---

## 1. 新 history.json 结构

```json
[
  {
    "schema_version": "1.0",
    "event_id": 1,
    "event_type": "history_initialized",
    "actor": { "type": "ai", "identity": "CodeBuddy agent (Hy3)", "detail": "..." },
    "source": { "user_prompt": "...", "model": "Hy3", "model_confidence": "confirmed", "tool": "CodeBuddy" },
    "operation": { "target_files": ["history.json"], "change_summary": "...", "sections_affected": [] },
    "correction": null,
    "comments": "...",
    "recorded_by": "ai",
    "recorded_at": "2026-10-03T14:56:00.585966+08:00"
  },
  {
    "schema_version": "1.0",
    "event_id": 2,
    "event_type": "plan_created",
    "..."
  }
]
```

- 顶层是**数组**，元素是 event 对象。
- 每个 event 自带 `schema_version`（event schema 版本）。
- 不再有 `events` 键、不再有文件级 meta。

---

## 2. event 字段（含 event 级 schema_version）

| 字段 | 类型 | 说明 |
|------|------|------|
| `schema_version` | string | **event 级** schema 版本（如 `"1.0"`），必填，置于每个 event 内 |
| `event_id` | int | event 在数组内的稳定序号（用于 `correction` 引用），自动分配 |
| `event_type` | string | 见 `references/record_types.md` |
| `actor` | object | `{type: ai|human, identity, detail}` —— 人机分离 |
| `source` | object | `{user_prompt, prompt_language, model, model_confidence, tool, session_id, attachments}` |
| `operation` | object | `{target_files, change_summary, sections_affected, diff_reference}` |
| `plan_state_snapshot` | object | 可选，自动附 `plan.md` 的 SHA-256 + 行数 |
| `correction` | object\|null | 仅 `correction` 事件填（见 §4） |
| `qna` | object\|null | 仅 `qna_recorded` 事件填（`question_ref/question/answer_summary/answer_location`） |
| `comments` | string | 不确定项备注 |
| `recorded_by` | string | `ai` / `human` |
| `recorded_at` | string | 写入时的真实时钟（ISO-8601），脚本自动填 |

> 与初版相比：**新增 `schema_version`（event 内）**；**删除** 顶层 `schema_version`/`plan_id`/`plan_title`/`created_at`；**删除** `timestamp`（时间看 `recorded_at`）。

---

## 3. 元信息（可选，单独文件 `history_meta.json`）

```json
{ "plan_id": "history_record_skill_plan", "plan_title": "Plan History Recorder Skill", "created_at": "2026-10-03T00:00:00+08:00" }
```

仅当需要 plan 级元信息时才存在；`history.json` 本身不依赖它，保持纯事件数组。

---

## 4. 只增不改与纠正

- 数组内每个 event **不可改**；纠错 = 追加 `correction` event（引用 `corrects_event_id`），原 event 不动。
- 从旧 object 包裹结构迁移到数组，是**一次性格式迁移**（执行阶段做），给旧 event 补 `schema_version` 即可，**不违反 event 级只增不改**。

---

## 5. append_history.py 修订（执行阶段）

- `init`：创建 `[]`（空数组）；可选同时创建 `history_meta.json`。
- `append`：读数组 → 压入 event；自动补 `event_id`（若缺，= `len+1`）、`schema_version`（若缺，= 当前默认版本如 `"1.0"`）、`recorded_at`、`plan_state_snapshot`；**只增不改**。
- `show`：遍历数组打印摘要（event 可能无 `timestamp`，显示需容错）。
- 不再处理外层包裹对象。

---

## 6. 迁移步骤（执行阶段）

1. 读取旧 `history.json`（object 形式），取出 `events[]`。
2. 给每个旧 event 补 `schema_version`（初版均为 `"1.0"`）。
3. 顶层 meta 移入 `history_meta.json`（若需要；否则丢弃）。
4. 写出为数组 `[]`。
5. 同步更新 `append_history.py`、`references/*`、`SKILL.md`、`assets/history.template.json` 以匹配新结构。

> `timestamp` 按 ①：旧 event 可保留亦可清理；新 event 一律不带。只增不改原则下，旧 event 保留 `timestamp` 也允许。

---

## 7. 关键规则（不变）

- **人机分离**：`actor.type` 必须真实；手动改动且无提示词时 `source.user_prompt="(manual edit - no prompt available)"`。
- **完整溯源**：AI 事件必须填全 `source`（提示词全文、模型、工具）；未知填 `unknown` 并在 `comments` 说明。
- **只增不改**：绝不用编辑工具改动已有 event；纠错靠追加 `correction` 事件。
- **诚实备注**：任何不确定一律写进 `comments`，不隐瞒。
- **问答留痕**：用户提问时，问题+答案写入 `questions.md`，并在 `history.json` 追加 `qna_recorded` 事件。
