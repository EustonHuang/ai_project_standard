## 0. 背景与目标

本计划不改变核心模型（append-only、文件夹化、锁+索引版本守卫、issues 兜底、`architecture_index` 的 implemented/latest 语义）。它只清理冗余并补齐 TOC。

六个改进来源：

- **Q11**：四个 `*_meta.json`（`history_meta`/`questions_meta`/`issues_meta`/`architecture_meta`）内容重复或为空，应删除；唯一有 plan 级价值的 `plan_id`/`plan_title`/`created_at` 并入 `architecture_index.json`；notes 类信息放进对应 `*_index.json` 的 `notes` 字段。
- **Q12**：root 的 `plan_001.md`、`plan_002.md` 完成过渡使命后多余——`architecture/001.md`、`architecture/002.md`（已含各自 §6 勾选与 §8 执行记录）才是规范副本；保留 `plan_00X.md` 只会造成"哪个是权威"的歧义。应删除。
- **Q13**：`questions_TOC.md` 作为"需手工维护的第三处"是多余的，应降级为**按需生成**的派生物。明确分工：**内容文件=真相源，索引=可重建缓存**，append 时由脚本更新，模型不读索引（上下文成本恒定，旧坑不回来）；`show` 加尾部窗口防膨胀。
- **Q14**：既然 TOC 对人和阅读友好、且由脚本派生，应把 TOC 扩展到四类（`architecture`/`history`/`questions`/`issues`），并给出统一写法方案（`gen-toc` 子命令 + append 自动刷新 + 截断）。
- **Q15–Q17**：Q15 暴露了 agent 会漏记 history（把"登记索引"误当"记录历史"）。要求：**任何 plan 文件改动都必须在同一回合追加 history 事件**。Q16 初版"收尾强制门"用全目录 mtime 扫描（不可扩展、并发误报），**已作废**；Q17 修订为 **CodeBuddy Hooks 驱动的本轮作用域强检**（不扫全盘、并发隔离），作为本计划的第四块工作（实现见 §5.2 / §6 / §8 步骤 4）。
- **Q18**：审计发现 history 两条数据质量问题——① `source.model` 全为 agent 自报 "Hy3"（平台无每轮模型信号），用户切换模型的轮次（疑似 #024 的 Hy4 preview）失真；② 删 `timestamp`（形态变更）时 `schema_version` 未 bump，仍冻结 "1.0"。要求：脚本改从**平台可信信号**取 model（未知即 `unknown`）、立 **schema_version bump 策略**并将常量升 `2.0`；旧记录不回改，由 `comment_added` #28 标注 lineage。作为本计划的第五块工作（实现见 §5.1 / §6 / §8 步骤 3）。

## 3. TOC 系统（四类 / gen-toc / 自动刷新 / 截断）

- **命名与位置**：每个板块一个 `<kind>_TOC.md`，放在 **plan 根**（与 `*_index.json` 同级，沿用"索引在根好找"的既定规则）。四类：`architecture_TOC.md`、`history_TOC.md`、`questions_TOC.md`、`issues_TOC.md`。
- **内容形态**（markdown + 相对链接）：
  - 顶部注释：`<!-- 自动生成，请勿手改；改动会被脚本覆盖 -->`。
  - 每项：`[label](相对路径) — 一句摘要`，摘要来自对应 `*_index.json` 的 brief：
    - history：`[001 · plan_created · 2026-10-03](history/001.json) — <change_summary>`
    - architecture：`[v001 · 初版设计](architecture/001.md) — 状态：已落地/待执行`
    - questions：`[Q1 · <问题>](questions/001.md) — <answer_summary>`
    - issues：`[001 · collision · open](issues/001/description.json) — <description>`
  - 相对链接保证在编辑器/GitHub 可点跳转。
- **生成方式**（脚本派生，不手改）：
  - 新增子命令 `gen-toc --plan DIR [--kind all|history|questions|issues|architecture]`：从各 `*_index.json` 渲染对应 TOC。
  - `append` 时**自动顺带重生成对应板块的 TOC**（索引已更新，渲染只多一次文件写，成本极低），保证 TOC 与索引一致、始终新鲜。
  - 人随时可 `gen-toc` 手动全量刷新。
- **长度控制**（防 TOC 自身膨胀）：
  - 只对**最近 N 条**出链（默认 200，可配置），末尾注明"更早记录见 `history/NNN.json` 或 `history_index.json`"，避免超长计划下 TOC 也变巨文件。
  - 机器检索仍走 `*_index.json`（不读 TOC），TOC 截断不影响程序化查找。
- **与既有的关系**：TOC = 索引的人类可读渲染，**同源**（都来自 `*_index.json`，单一真相源）。索引负责"机器高效读/写"，TOC 负责"人类点链接浏览"，二者由脚本从同一份 index 派生，不会分叉。

## 4. show 改进（尾部窗口，防索引膨胀回到旧坑）

- `show --plan DIR [--kind ...] [--last N]`：默认只打印最近 N 条 brief（默认如 `--last 50`），不全量载入；`--last 0` 表示全部。
- `architecture` 的 show 不变（版本表本来就短）。
- 关键分工不变：**append 时模型不需要读索引**，脚本在磁盘上读索引、算 `max_id`、写新文件、更新索引——上下文成本恒定，最初的坑已彻底解决。索引/brief 增长只影响 `show` 与 `gen-toc`；内容文件才是真相源，最坏情况 `rebuild-index` 从内容重算，不丢数据。

## 5. 脚本变更（`scripts/append_history.py` + 新增 `scripts/turn_gate.py`）

### 5.1 `append_history.py`
- `init`：不再创建任何 `*_meta.json`；`--meta plan_id title` 改为写入 `architecture_index.json` 的 `plan_id`/`plan_title`/`created_at`。其余四类 `*_index.json` 照旧创建（可含空 `notes`）。
- `gen-toc`（新增子命令）：`gen-toc --plan DIR [--kind all|history|questions|issues|architecture]` 渲染四类 TOC。
- `_regen_toc(plan, kind)`（通用函数）：替代原 `_regen_questions_toc`；按 §3 模板渲染；截断到最近 N 条。
- `append`：写入后调用 `_regen_toc`；解析 `source.model` **优先取平台可信信号**（env `CODEBUDDY_MODEL` 或 hook 上下文 model），取到 `model_confidence="confirmed"`、取不到写 `"unknown"` 并注 `comments`，**禁止 agent 自报 "Hy3"**（Q18）；`EVENT_SCHEMA_VERSION` 升 `"2.0"`（反映"无 timestamp"形态，Q18，策略见 §6）。
- `rebuild-index` / `set-implemented`：重建/推进后顺带 `_regen_toc`。
- `migrate`：不再生成/迁移 meta；旧 `history.json`/`questions.md` 删除步骤不变。
- 保留：`audit`、`recover`、`show`（尾部窗口）。

### 5.2 新增 `scripts/turn_gate.py`（防漏记强制门：Q15–Q17）
- 子命令：`begin`（开轮写 `.turn/<session_id>.json`）、`record`（PostToolUse 记账）、`end`（Stop 强检，必要时 `exit 2`）、`check --changed <file>...`（声明式手动核查，非扫描）。
- 状态文件：`<plan root>/.codebuddy/hooks/.turn/<session_id>.json`（`baseline_max_id` + `declared[]` + `ts`）。
- 机制（本轮作用域、不扫全盘、按 `session_id` 隔离）：`UserPromptSubmit`→`begin` 记 `baseline_max_id`；`PostToolUse`（matcher `write_to_file|replace_in_file|delete_file|Write|Edit`）→`record` 把 `filePath` 追加 `declared[]`；`Stop`→`end` 强检 `declared[]` 非空时须存在 `event_id > baseline_max_id` 的新事件且 `target_files` 覆盖 `declared[]`，否则输出未覆盖清单并 `exit 2`。成本 O(本轮改动数)，并发正确（清单按 session 隔离；非 plan 内文件忽略）。
- Hook 配置（写进 `<workspace>/.codebuddy/settings.json`，**timeout 20/20/30**——原 Q17 的 10/10/15 已翻倍）：

```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command",
        "command": "python3 \"$CODEBUDDY_PROJECT_DIR/.codebuddy/skills/plan-history-recorder/scripts/turn_gate.py\" begin",
        "timeout": 20 } ] }
    ],
    "PostToolUse": [
      { "matcher": "write_to_file|replace_in_file|delete_file|Write|Edit",
        "hooks": [ { "type": "command",
          "command": "python3 \"$CODEBUDDY_PROJECT_DIR/.codebuddy/skills/plan-history-recorder/scripts/turn_gate.py\" record",
          "timeout": 20 } ] }
    ],
    "Stop": [
      { "hooks": [ { "type": "command",
          "command": "python3 \"$CODEBUDDY_PROJECT_DIR/.codebuddy/skills/plan-history-recorder/scripts/turn_gate.py\" end",
          "timeout": 30 } ] }
    ]
  }
}
```

- `audit` 保持纯结构校验（ID 连续、索引与文件一致），不做 mtime 全盘扫描；hook 配置本身（`.codebuddy/settings.json`）也是工程文件，改动须按规则进 history（dogfooding）。
