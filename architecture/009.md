## 0. 背景与需求

### 0.1 目标

把一个 CodeBuddy session 的**一切 input/output** 落成有序 trace：用户 prompt、agent 回答正文、agent 的 reasoning、每次 skill 调用、每个被写文件、每次 web search、**hook 触发本身及其副作用**、命令执行与输出。要求（Q39→Q44 讨论弧的结论）：

1. **记录器活在 agent 之外**——agent 若自录，每次记录动作又成为需记录的 agent 动作，无限回归（log-the-log 死循环）。
2. **hooks 是 output 的一部分**：hook 触发本身要作为一等事件入 trace，不是被隐藏的机制。
3. 结构化溯源（`history/`）保持轻量；trace 与之解耦，history 事件可**引用** trace 路径，不内嵌逐字正文。

### 0.2 核心原则（实现者必须遵守）

- **P1｜daemon 是 trace 唯一写入者。** 任何组件不得直接写 trace 文件，只经 feeder → daemon socket。
- **P2｜agent 永不写 trace。** agent 的一切活动是被观察对象；agent 可选的「自发射」（§6）也走 feeder 通道，不直写文件。
- **P3｜记录器故障不得影响会话。** feeder 连不上 daemon 时写 spool 后**静默 exit 0**，绝不阻塞 agent 流程。
- **P4｜hook 事件照录。** 每次 hook 触发（UserPromptSubmit/PreToolUse/PostToolUse/Stop）记成 `{kind:"hook",...}`；gate 副作用（turn_gate 记账/拦写）经 watcher 从 `.turn` 落盘状态补捕。

## 1. 设计决策

| 决策 | 内容 |
|---|---|
| **D1｜进程外 daemon** | 独立长驻进程监听 Unix domain socket，是 trace 唯一写入者；其写是 OS 文件 I/O，不被回灌进 agent 工具流 → 无死循环。 |
| **D2｜hooks 作 push 通道** | hooks 是 **IDE 外部运行的命令**（非 agent 工具调用）：UserPromptSubmit/PreToolUse/PostToolUse/Stop 各挂一个 feeder 把结构化 payload 推给 daemon。拿得到 prompt 原文、工具名、input/output。与既有 `turn_gate` hooks **并存**（同事件数组追加，不替换）。 |
| **D3｜被动 watcher 作交叉校验** | daemon 内嵌 watcher 线程，fsevents/kqueue（无则 1s 轮询）观察：① CodeBuddy 会话 transcript（若实测可得，第 0 步）；② 各 plan 的 `.codebuddy/hooks/.turn/` —— 把 turn_gate 的落盘副作用（`declared` 记账、baseline、拦写痕迹）作为 ground truth 捕获，与 hook payload 是否送达无关。 |
| **D4｜trace 在 plan root 之外** | 默认 `~/.ai_project_standard/session_trace/<plan_slug>/<session_id>.jsonl`（env `RECORDER_TRACE_DIR` 覆盖根目录）。在 plan root 外 → 不经 turn_gate 白名单/拦截、不污染仓库。 |
| **D5｜opt-in 安装** | 仅运行 `install-session-recorder` skill 才写 hooks 接线并拉起 daemon；未安装项目零改动（非 breaking 的保证）。 |

## 2. 组件与落盘布局

```
框架仓 scripts/
  session_recorder.py        ← daemon：socket 服务 + trace 落盘 + spool 排水 + watcher
  recorder_feed.py           ← feeder：stdin payload → socket；失败落 spool

采纳项目（安装后）
  .codebuddy/settings.json   ← 既有 4 事件数组各追加一条 recorder_feed hook
  .codebuddy/skills/install-session-recorder/

用户级（plan root 之外）
  ~/.ai_project_standard/
    runtime/recorder.sock    ← socket（env RECORDER_SOCK 覆盖）
    session_trace/<plan_slug>/<session_id>.jsonl   ← trace
    spool/*.jsonl            ← feeder 降级队列（daemon 启动时排水）
```

### 2.1 trace 行 schema（每行一个 JSON 对象）

```json
{
  "seq": 42,                       // 每 trace 文件内单调递增，daemon 分配
  "ts": "2026-10-24T10:00:00.123+08:00",
  "kind": "tool_call",             // 见下表
  "name": "PostToolUse",           // kind=hook 时为 hook 名；kind=tool_* 时为工具名
  "plan_id": "ai_project_standard",
  "session_id": "cc41ed41...",
  "payload": { }                   // 原样保留 hook/feeder 给到的 JSON
}
```

| kind | 来源 | 内容 |
|---|---|---|
| `prompt` | UserPromptSubmit hook | 用户 prompt 原文（payload 原样） |
| `tool_intent` | PreToolUse hook | 即将执行的工具与入参（含被拦的尝试） |
| `tool_call` | PostToolUse hook | 工具名 + input/output —— 覆盖文件写、skill 调用、web search、命令 |
| `turn_end` | Stop hook | 本轮收尾 |
| `hook` | daemon 对每条 hook 触发的自记 | `{hook: 名, exit, ms}`（hook 本身被记录，P4） |
| `watcher` | watcher 线程 | `.turn` 状态变化 / transcript 增量的观察摘要 |
| `reasoning` | agent 自发射（§6，可选） | agent 的推理摘要（陈述式，非原始隐藏 CoT） |
| `answer` | agent 自发射（§6，可选） | agent 最终回答正文 |
| `lifecycle` | daemon | daemon start/stop、spool 排水、异常 |

## 3. Daemon 规范（`session_recorder.py`）

```bash
python3 scripts/session_recorder.py start [--foreground]   # 幂等：已有存活 daemon 则 exit 0
python3 scripts/session_recorder.py stop
python3 scripts/session_recorder.py status                 # 打印 pid/uptime/各 trace 行数
python3 scripts/session_recorder.py doctor                 # 覆盖对账：已知 projects/sessions、各 trace 最后事件时间、spool 积压、「有 .turn state 无 trace」缺口清单（Q46 机制 4）
```

- **Socket 服务**：监听 `~/.ai_project_standard/runtime/recorder.sock`（env `RECORDER_SOCK` 覆盖），accept 逐行 JSON。启动前若 socket 文件残留，先 `connect` 探测：连不上即删除重建，连得上说明 daemon 已在（幂等退出）。
- **落盘**：按 `(plan_id, session_id)` 路由到 trace 文件；append 一行 + flush；`seq` 从 1 单调递增（daemon 内存计数，启动时扫文件尾恢复）。
- **Spool 排水**：启动时按文件名时间序重放 `spool/*.jsonl` 到对应 trace，成功后删除；排入 `lifecycle` 事件。**坏行跳过**：trace 为 append-only，崩溃可能留半行 JSON——读侧按行解析失败即丢弃该行并记 `lifecycle` 警告事件（Q45）。
- **Watcher 线程**（D3）：优先 `watchdog`（macOS fsevents）；未安装则 1s 轮询。观察路径列表：各已知 plan 的 `.codebuddy/hooks/.turn/` + `RECORDER_TRANSCRIPT_PATH`（env，实测出 CodeBuddy transcript 路径后配置；未配置则跳过）。变化即产生 `watcher` 事件（内容摘要，不复制全文；transcript 若可用则记增量 offset 追读）。**`.turn` 普查（Q46 机制 3）**：turn_gate 强制接线 → 每个 session 必留 `.turn/{session_id}.json`（turn_gate.py L45–46），故 `.turn` 目录 = 该项目「存在过的 session 全集」ground truth；watcher 枚举新 state 文件对账——**有 state 无对应 trace = 覆盖缺口**，立即记 `watcher` 缺口事件（feeder 全失效也能点名）。
- **单实例多项目（粒度，Q45）**：**一个 daemon 服务本用户全部项目**——不是 per-project，更不是 per-session/per-answer。session 与 answer 只是**记录粒度**（trace 文件 / trace 行），不是进程粒度；事件自带 plan_id/session_id 两键路由分文件，跨项目无共享文件，单线程 append 天然串行无锁竞争。

### 3.1 生命周期（Q45）

- **启动三路径**：① launchd LaunchAgent（`RunAtLoad=true` + `KeepAlive=true`，登录即拉、崩溃自动重启——**主路径**，`install-session-recorder` 负责写 plist；Linux 等价 systemd user unit）；② **feeder 兜底拉起**（connect 失败 → `setsid` spawn daemon → 重试一次 → 仍失败落 spool）；③ 手动 `start [--foreground]`。
- **优雅退出**：`stop` 发 SIGTERM → 停 accept → 排空 in-flight 事件 → flush trace → 删除 socket 文件 → exit 0；SIGINT 同义。
- **崩溃/被杀（含 kill -9）**：无清理机会，socket 残留 → 下次启动 `connect` 探测：连得上 = 已有存活实例（幂等 exit 0），连不上 = 死残留（删除重建）；launchd `KeepAlive` 自动重拉。崩溃窗口内 feeder 走 spool，不丢事件、会话零影响（P3）。
- **恢复链**：重拉 → socket 残留探测清理 → spool 排水重放（时序以 spool 文件名 ts 保真）→ 缺口由 `doctor` 对账点名。

## 4. Feeder 规范（`recorder_feed.py`）+ hook 接线

```bash
recorder_feed --kind prompt < hook_stdin.json     # payload 从 stdin 读
recorder_feed --kind tool_call --name PostToolUse < payload.json
recorder_feed --kind answer --text "回答正文"      # agent 自发射用（§6）
```

- 读 stdin（hook 的 JSON payload）或 `--text`，连 socket 发送；**超时 200ms**。
- 失败（daemon 不在/超时）：先**兜底拉起**——`setsid` spawn `session_recorder.py start` → 重试连接一次；仍失败则原子追加 `spool/<ts>-<rand>.jsonl`，**静默 exit 0**（P3）。`--strict` 才允许非零退出（仅调试用）。

### 4.1 安装时写入 `.codebuddy/settings.json`（幂等：已存在则跳过）

在既有 hook 数组**追加**（不替换 turn_gate 条目）：

| 事件 | 追加命令 |
|---|---|
| UserPromptSubmit | `recorder_feed --kind prompt` |
| PreToolUse | `recorder_feed --kind tool_intent --name <tool>` |
| PostToolUse | `recorder_feed --kind tool_call --name <tool>` |
| Stop | `recorder_feed --kind turn_end` |

每次这些 hook 命令执行，daemon 还会记一条 `{kind:"hook", name, exit, ms}` —— **hook 触发本身入 trace**（P4）。

## 5. 循环安全论证（实现者在代码注释中保留）

agent 从不写 trace（P2）。agent 可选自发射经 `execute_command` 调 feeder：这是一次工具调用，`PostToolUse` 对它**只触发一次** → 产生一条 `tool_call` 事件 + 一条 `answer`/`reasoning` 事件，不再触发后续 hook；daemon 对 trace 的写是 OS I/O，不回灌 agent 工具流。故无 log-the-log。

## 6. agent 自发射（可选，安装项目自行决定是否启用 RULE 条款）

- 每轮结束 agent 以 `execute_command` 调 `recorder_feed --kind answer --text <最终回答正文>`；如需留推理摘要，再调 `--kind reasoning`。
- 这补齐 hooks 拿不到的两样：agent 回答正文与推理（thinking 的诚实边界：`reasoning` 是**陈述式摘要**，非平台原始 CoT；平台若在 hook payload 暴露 reasoning 字段则直采，见 §7）。

## 7. 第 0 步实测清单（实现前置，结果记入 questions）

1. 同一 hook 事件能否挂多条命令（turn_gate + recorder_feed 并存）。
2. `UserPromptSubmit` payload 是否含 prompt 文本；`PostToolUse` 是否含 tool_input/tool_output。
3. `Stop` payload 内容。
4. CodeBuddy 是否持久化会话 transcript（路径/格式/可 tail？）→ 决定 watcher 是否有目标 ①。
5. hook 进程可用环境变量（session/plan 识别用，如 `CODEBUDDY_PROJECT_DIR`；session_id 已证实取自 `CODEBUDDY_SESSION_ID`/`CODEBUDDY_CONVERSATION_ID`，turn_gate.py L39–42）。
6. CodeBuddy 是否支持**用户级/全局 hooks**——支持则一次安装覆盖用户全部项目（Q46 的理想覆盖路径），否则维持 per-project 安装 + audit 点名（Q46 兜底）。

任一项不满足的降级路径：②不可得 → tool_call 只有工具名与入参摘要；④不可得 → watcher 只看 `.turn`，回答正文只能靠 §6 自发射。

## 10. 验收

1. **未安装零影响**：框架仓与未安装项目 `audit` 通过，settings.json 无新增条目，无新文件落入 plan root。
2. **全链路**：安装后发一条 prompt → trace 出现 `prompt`；调用一次工具 → `tool_intent` + `tool_call`；每次 hook 触发有 `hook` 事件；Stop 后有 `turn_end`。
3. **hooks-in-output**：turn_gate 记账后，`.turn` 变化产生 `watcher` 事件。
4. **降级不丢**：杀掉 daemon 后再操作 → 会话不受影响、feeder 全落 spool；重启 daemon 后 spool 排空、事件按原时序入 trace。
5. **自发射无递归**：启用 §6 后一轮产生 1 条 `answer` + 恰 1 条对应 `tool_call` 事件（无膨胀）。
6. **位置正确**：trace/spool 均在 plan root 之外；`turn_gate` 不记账、`audit` 不检查它们。
7. **覆盖可查（Q45/Q46）**：杀 daemon 后产生事件 → `doctor` 列出 spool 积压；重启排水后清零。人为删掉某 session 的 trace 文件 → `doctor` 经 `.turn` 普查点名该缺口；未装 recorder 但已装 turn_gate 的项目被 `check-standard`/`audit` 点名。
8. **生命周期（Q45）**：`stop` 优雅退出无残留 socket；`kill -9` 后重启幂等恢复；崩溃窗口内会话零影响（feeder 静默落 spool）。
