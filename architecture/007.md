# 网关强化：.turngateignore 通用忽略 + PreToolUse 写时硬拦截 — architecture 007 / 目标 v0.7

> **状态：待执行（planned）。** 本计划吸收采纳方项目（euston_personal_experience_summary）实际事故与 Q11/Q12 讨论结论，统一在下一框架版本（v0.7）落地。根因：agent 临时事件文件落于 plan root 内，被 turn_gate 记账且未被历史事件覆盖，导致 end 守卫误判阻断回合；Q11 指出硬编码忽略 `.tmp/` 是头痛医头，Q12 指出 workflow 约定无法强制落盘位置。本文件即 v0.7 权威计划；`architecture_index.json` 的 `latest_version` 升 7，`implemented_version` 待执行后置 7。

## 0. 背景与三项设计决策

- **事故复盘**：agent 调用 `append_history.py` 前，把临时事件文件 `event_006.json` 建在 plan root，用完删除；turn_gate 的 `record` 仍把它记为「本轮 plan 改动」，end 守卫发现其未被任何 `id>5` 历史事件 `target_files` 覆盖 → `exit 2` 阻断回合。结论：临时文件载体绝不能落在 plan root 内，或必须被守卫显式忽略。
- **Q11（跨项目引用 `euston_personal_experience_summary/questions/011.md`）**：在 `turn_gate.py` 硬写 `rel.startswith(".tmp/")` 是头痛医头——每多一种 scratch 模式就要改引擎。正确抽象是 plan root 下的 **`.turngateignore`**（gitignore 语法），忽略规则变项目级配置而非引擎常量。
- **Q12（跨项目引用 `euston_personal_experience_summary/questions/012.md`）**：`workflow.md` 的约定本身不能强制 agent；现存 turn_gate 仅「软守卫」（事后失败、不拦截）。需要 **PreToolUse 写时硬拦截 hook** 作兜底。

三项决策（软约定 + 两机制层）：
- **软约定（Q12 原文要求，落 `references/workflow.md`）**：临时 event 文件**统一放 `<project>/.tmp/`**，守卫**已豁免**，**无需任何历史事件覆盖**（机制见 D1：`.tmp/` 已列入 `.turngateignore`，turn_gate 不记账）。此为软层——纯文档约定，本身不强制 agent。
- **D1（通用忽略）**：引入项目级 `.turngateignore`（gitignore 语法），turn_gate 读它并对命中路径不做记账、不要求覆盖事件。引擎只负责「读 + 匹配」。该机制正是「软约定」中「守卫已豁免」的实现基础。
- **D2（硬拦截）**：新增 PreToolUse hook，在 `write_to_file`/`replace_in_file`/`delete_file` 之前校验目标路径；允许 = 受管文件类别 OR 命中 `.turngateignore`，否则拒绝写入。软 end 守卫保留作最后兜底。此即 Q12 要的「忘了也能强制」的硬兜底。

## 1. D1 — `.turngateignore` 通用忽略配置

### 1.1 位置与格式

- 位于 plan root：`<plan>/.turngateignore`。
- 语法 = gitignore（支持 `*`、`**`、`/` 前缀/后缀、`#` 注释、取反 `!`）。
- 默认随框架发布，内容含：

  ```
  # 框架默认忽略：临时载体与 scratch
  .tmp/
  *.tmp
  *.tmp/
  ```

- 项目可覆盖/追加（在自身 `.turngateignore` 增删模式）；引擎不内置任何硬编码忽略常量。

### 1.2 语义（turn_gate 行为）

- `record`：目标路径命中 `.turngateignore` → 不计入本轮 `declared`。
- `end`：仅校验未被忽略且未被历史事件覆盖的 in-plan 文件；命中忽略者直接放行。
- 引擎实现 = 读 `.turngateignore` → 编译为匹配器 → 对 `norm_rel(path)` 命中则跳过。无硬编码 `.tmp/`。

### 1.3 收益（回应 Q11）

- 忽略规则是**项目级配置**，任意项目自声明 scratch（`.tmp/`、构建产物、编辑器临时文件），无需改 `.plan-standard` 引擎；
- 引擎职责单一（读+匹配），稳定；
- 与 `.gitignore` 心智一致，可同步维护。

## 2. D2 — PreToolUse 写时硬拦截 hook

### 2.1 触发与判定

- 触发：在 `write_to_file` / `replace_in_file` / `delete_file` **之前**（PreToolUse）。
- 判定：`允许` 当且仅当 目标 ∈ **受管文件白名单** 或 命中 **`.turngateignore`**；否则返回非零退出码，**拒绝写入**。
- 效果：一旦 agent 把临时文件随手建在 plan root 非 `.tmp/` 处，立刻被挡回，逼其放入 `.tmp/`。
- 与 D1 共用同一份 `.turngateignore`，二者配套。

### 2.2 软/硬分工

- 硬拦截（PreToolUse）= 第一道、写时阻止，杜绝误建；
- 软 end 守卫（现有）= 最后兜底，捕获任何漏网（如 hook 未覆盖的工具），保持既有行为。

### 2.3 安全性边界

- 白名单必须覆盖所有合法受管路径，否则会误伤正常编辑（见 §3）；
- 命中 `.turngateignore`（如 `.tmp/`）则放行，不拦截正常 scratch 写入。

---

## 3. 受管文件白名单（Managed Allowlist）

硬拦截的「允许」一侧需枚举全部合法受管路径类别；任何不在此列、又不命中 `.turngateignore` 的 in-plan 写操作一律拒绝。当前类别：

- `architecture/`（含 `architecture/NNN.md`）、`architecture_index.json`、`architecture_TOC.md`
- `questions/`、`questions_index.json`、`questions_TOC.md`
- `history/`、`history_index.json`、`history_TOC.md`
- `issues/`、`issues_index.json`、`issues_TOC.md`
- `improvements/`、`improvement_index.json`、`improvement_TOC.md`
- `references/`、`scripts/`、`skills/`、`assets/`
- `standard_version`、`.codebuddy/settings.json`
- **`.turngateignore` 本身**：作为忽略声明文件，允许被创建/编辑（视为配置类，放行）；其修改即调整后续忽略范围。

> 注：白名单与 `references/workflow.md` 的「受管文件」定义必须保持单一来源，避免硬拦截与既有约定漂移。

---

## 4. 与 git / .gitignore 协同

- `<plan>/.gitignore` 应忽略 `.tmp/`（及与 `.turngateignore` 一致的模式），避免 scratch 误提交；
- `.turngateignore` 与 `.gitignore` 可部分重叠但职责不同：前者给 turn_gate 用（记账/拦截），后者给 git 用（提交）。建议项目将 `.tmp/` 同时列入两者。
