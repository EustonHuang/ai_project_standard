# 自定义栏目（Custom Feature）：注册制 + `custom/` 容器 + 按 feature 同步 — architecture 008 / 目标 v0.8

> **状态：待执行（planned）。** 框架**不预置任何自定义栏目**——谁都不能预测一个项目需要什么。项目需要哪个，就用 `register-custom-feature` 注册哪个；注册后它才有 `custom/<feature>/`、`<feature>_index.json`、`<feature>_TOC.md`，才受审计与留痕管辖。本文件即 v0.8 权威计划；`architecture_index.json` 的 `latest_version` 升 8，`implemented_version` 待执行后置 8。

---

## 0. 背景与需求

### 0.1 目标结构

```
custom/<feature>/              ← 记录目录，例 custom/topic_plan/
custom/<feature>_index.json    ← 例 custom/topic_plan_index.json
custom/<feature>_TOC.md        ← 例 custom/topic_plan_TOC.md
```

index/TOC 与 feature 文件夹**并列放在 `custom/` 内**，不在项目根。

### 0.2 现状缺口

五大栏目（`history/ questions/ issues/ improvements/ architecture/`）在 `append_history.py` 中由 `CATEGORY_DIR` 常量写死，索引/TOC/审计/网关白名单都照这五个写。项目自己的领域产物（euston_wiki 的 topic plan）只能自带脚本手工维护 `topics_index.json`，与框架索引不同构、不进 `audit`、不受 turn_gate 记账，等于脱离留痕体系。

### 0.3 四项设计决策

- **D1｜注册制**：`custom_categories.json` 是唯一真相；框架不预置任何 feature，注册是唯一入口。
- **D2｜目录格式**：框架只规定「序号开头」与「同名辅助目录」，其余命名自由。
- **D3｜记录规范**：一条记录 = 一个编号 md 文件（含可选同名辅助目录），形态见 D2；不另加 frontmatter 或版本机制。
- **D4｜同步与留痕**：改哪个 feature 就只重建那个 feature 的 index+TOC；两者都必须进 history。

## 1. D1 — 注册：`custom_categories.json`

位于**项目根**（与 `standard_version`、`.turngateignore` 同级），是「哪些 `custom/<feature>/` 受管」的唯一真相。

```json
{
  "categories": [
    {
      "name": "topic_plan",
      "description": "项目领域的 topic 计划（含 spark/rdd 等主题）"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | feature 目录名；字母/数字/`_`/`-` |
| `description` | ⬜ | 一句话说明 |

schema 只含这两项：注册机制本身只需要「有没有这个 feature」这一信息，不为假想的通用性加配置项。

注册动作由 skill `register-custom-feature` 完成（命令等价形式见 §5.1）：

1. 查 `custom_categories.json` → **已注册则提示「已注册」并终止**（exit 2，不改任何文件）。
2. 未注册 → 追加一项、建 `custom/<name>/`、生成空的 index+TOC。

---

## 2. D2 — 目录格式（框架只规定两件事）

```
custom/topic_plan/
  001-spark-helloworld.md          ← 一条记录（序号开头）
  001-spark-helloworld/            ← 该记录的辅助说明（同名目录）
      spark-introduction.md
  002-rdd.md                       ← 另一条记录
```

**规定只有两条：**

1. **记录文件必须以零填充序号开头**：`001-spark-helloworld.md`、`002-rdd.md`。分隔符与 topic 命名由项目自定——`001_spark_helloworld.md` 同样合法，框架不规定。
2. **需要额外文件时，用与记录同名的目录**：`001-spark-helloworld/`。辅助文件归属于哪条记录，靠「目录名 = 记录文件名（去 `.md`）」对应，不会含糊。

其余（是否再分子目录、topic 用什么语言、一个 feature 放多少条记录）框架不管——**每个 custom feature 有自己的内部格式，本规范不明文指定**。

index/TOC 放在 `custom/` 内、与 feature 文件夹并列（§0.1）。

---

## 3. D3 — 记录规范

一条记录 = 一个编号 md 文件，外加可选的「同名辅助目录」——形态完全由 D2 规定，本规范**不另加 frontmatter、不另加版本/修订机制**。

`<feature>_index.json` 与 `<feature>_TOC.md` 由同步逻辑（§4.1）从磁盘**推导**得出，不依赖任何 frontmatter：

- `num` / `topic`：取自文件名（`001-spark-helloworld.md` → num=001，topic=spark-helloworld）。
- `file`：记录文件路径。
- `aux_files`：若存在同名辅助目录（如 `001-spark-helloworld/`），其下文件列入。

「有序」已由文件名序号保证；记录的增删改即文件的增删改，无需额外约定。

---

## 4. D4 — 同步与留痕

### 4.1 只同步「被改动的那个 feature」

| 触发 | 动作 |
|---|---|
| 写 `custom/<feature>/**` | 只重建 `custom/<feature>_index.json` + `custom/<feature>_TOC.md` |

**严禁顺带重建其它 feature 的 index/TOC。** 由 PostToolUse hook 自动完成（§5.3），也可手工执行 `custom sync --name <feature>` 或 `--all`。

### 4.2 双录

一次 custom 改动必须同时落到四处：记录文件 + 该 feature 的 index + TOC + 一条 history 事件。history 事件的 `operation.target_files` 要列全这三者，否则 Stop 时 turn_gate 拦截（exit 2）。

### 4.3 网关与审计

- `custom/` 与 `custom_categories.json` 加入受管白名单（`turn_gate.py`）+ RULE.mdc 的受管文件清单。
- `audit` 按注册清单检查：目录存在、index/TOC 存在、index 与磁盘记录一致。**未注册任何 feature 时全部跳过**，对既有项目零影响。

## 5. 命令、skill 与 hook 接线

### 5.1 命令（`append_history.py custom`）

```bash
# 注册（幂等：已注册则提示并终止）
python3 scripts/append_history.py custom register --plan . --name topic_plan \
    [--description "..."]

# 只同步一个 feature
python3 scripts/append_history.py custom sync --plan . --name topic_plan
# 同步全部已注册 feature
python3 scripts/append_history.py custom sync --plan . --all

# 列出已注册 feature
python3 scripts/append_history.py custom list --plan .
```

`gen-toc --kind all` 会顺带重建所有已注册 feature 的 TOC。

### 5.2 Skill：`register-custom-feature`

位于框架 `skills/register-custom-feature/`；安装标准时随引擎一起分发到采纳项目的 `.codebuddy/skills/register-custom-feature/`，**所有采纳项目都能用**。

- 参数：custom-feature 名（如 `topic_plan`）。
- 行为：查 `custom_categories.json` → 已注册则提示并终止 → 未注册则写入清单、建目录、生成 index+TOC。

### 5.3 Hook 接线（`.codebuddy/settings.json`，install-standard 写入）

| 事件 | 命令 | 作用 |
|---|---|---|
| UserPromptSubmit | `turn_gate.py begin` | 记录本轮基线 |
| PreToolUse | `turn_gate.py prewrite` | 受管白名单硬拦截（含 `custom/`） |
| PostToolUse | `turn_gate.py record` | 记账 + **按 feature 重建 index/TOC** |
| Stop | `turn_gate.py end` | 未进 history 则拦（exit 2） |
