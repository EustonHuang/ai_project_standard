## Q26 — 2026-10-05
**问题：** 用户质疑：安装项目规范后，CodeBuddy IDE 是否会像 Claude Code 读 CLAUDE.md 那样自动读 `.codebuddy/rules` / `CODEBUDDY.md`？甚至怀疑 IDE 是否真的读 hook。要求实际调查 CodeBuddy 生态是否存在、是否需要设置、架构怎样。

**答案（基于官方文档实证 + 本机 `.codebuddy` 探查）：**

CodeBuddy 生态**确实存在**类 CLAUDE.md 的自动注入机制，且不止一种，但触发条件各有讲究：

- **`CODEBUDDY.md`（项目根，无 frontmatter）**：官方明确"默认会将原文全文放入上下文"；兼容 `AGENTS.md`（有 AGENTS.md 且无 CODEBUDDY.md 时自动加载）。行为等同 CLAUDE.md 的自动注入——用户"它不会像 Claude Code 那样读根说明文件"的担心对 CODEBUDDY.md **不成立**。
- **`.codebuddy/rules`**：每条规则是**文件夹 + `RULE.mdc` + frontmatter**（`description`/`alwaysApply`/`enabled`/`updatedAt`/`provider`），**不是直接丢 .md**。三类：①总是(`alwaysApply:true`)：新会话开始注入原文，全程生效；②智能体请求(`false`)：开始仅注入名称+描述，agent 判断相关时自动读原文；③手动：需 `@规则名`。
- **`.codebuddy/skills`**：`SKILL.md` 的 `name`+`description`(~100词)**常驻上下文**，匹配场景时自动加载正文(<5k词)，无需命令。

**对用户两个怀疑的判定：**
- "不读 CODEBUDDY.md/.codebuddy/rules" —— 部分不成立（上述两者确有自动注入）。
- "怀疑有没有读 hook" —— 文档层面**无法证伪**：Overview/Rules/Skills 三页**完全未提 hooks**，公开文档无法保证 IDE 执行 `.codebuddy/settings.json` 里的 hooks。

**两个致命限定：**
1. 自动加载只在**会话开始**发生一次；修改/新增后须**新建会话**才生效，当前会话不重载。
2. 框架仓库自身**未用**任何自动加载机制（根无 CODEBUDDY.md、无 .codebuddy/rules、未装成 .codebuddy/skills），只写了 hooks——把"agent 是否照规范"的赌注全押在 hooks 上，而 hooks 恰是文档未记载、无法保证执行者。

**对框架的修正建议（取代 Q25 的初步建议）：**
- install 应改为：① 在项目根生成 `CODEBUDDY.md`（或 `AGENTS.md`，零格式、默认全文注入，最贴近 CLAUDE.md）；或 ② 写 `.codebuddy/rules/<name>/RULE.mdc` + `alwaysApply:true`（须新会话生效）；或 ③ 把标准做成 `.codebuddy/skills/ai-project-standard/SKILL.md`（元数据常驻、场景自动触发）。
- hooks 基石须**实测**：IDE 改受管文件看日志是否出现 turn_gate begin/record/end、漏记是否 exit 2；若 IDE 不执行 hooks，强制门整体失效。
