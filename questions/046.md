## Q46 — 2026-10-24

**问题：**
怎么保证每个项目、每个 session 都被录到？我可能同时在多个项目跑多个 session，怎么保证？

**答案：**

### 一、覆盖模型：安装粒度 per-project，覆盖粒度 per-session 自动

关键：hooks 写进项目的 `.codebuddy/settings.json` 是**一次性安装**；此后该项目**每个 session 自动触发**，无需任何 per-session 动作。session 身份来自 hook 进程的环境变量——`turn_gate.py` L39–42 已证实：`session_id()` 取 `CODEBUDDY_SESSION_ID` / `CODEBUDDY_CONVERSATION_ID`（兜底 `local-<pid>`）。因此：

- 同一项目**并发多 session**：各有独立 session_id → daemon 按 `(plan_id, session_id)` 路由到各自 trace 文件，互不串线；
- daemon 单线程 accept 逐行 append，天然串行，无锁竞争；
- **多项目**：共用同一 daemon（Q45：单实例 per 用户），按 plan_id 分文件。

### 二、完整性四机制（怎么「保证」）

1. **hooks 自动触发（覆盖的根基）**：feeder 挂在 4 个 hook 事件上，IDE 对每个 session 的每个事件都触发 → 有 session 必有事件流，不依赖人或 agent 记得做什么。
2. **spool 兜底（不丢）**：daemon 不在/超时 → feeder 原子落 spool、静默 exit 0；daemon 重启排水重放。崩溃窗口内的事件不丢。
3. **`.turn` 普查（session 全集对账，关键机制）**：turn_gate 是框架强制接线，**每个 session 必在 `.codebuddy/hooks/.turn/` 留一个 `{session_id}.json`**（L45–46）。故 `.turn` 目录 = 该项目「存在过的 session 全集」的 ground truth。daemon watcher 枚举 `.turn` 新文件 → 对账：**有 state 文件但无对应 trace = 覆盖缺口** → 立即记 `watcher` 缺口事件并告警。即使 feeder 全部失效，缺口也能被点名。
4. **`doctor` 对账命令（可审计）**：`session_recorder.py doctor` 列出：已知 projects/sessions、每 trace 最后事件时间、spool 积压、以及「有 `.turn` 无 trace」的缺口清单。完整性从「自信」变成「可查」。

### 三、per-project 覆盖怎么保证

- **理想路径**：若 CodeBuddy 支持**用户级 hooks**（全局 settings），一次安装即覆盖用户全部项目，彻底消除「忘装某项目」。→ 列入第 0 步实测（§7 新增第 6 项）。
- **兜底路径**：per-project 安装 + `check-standard`/`audit` 新增检查——**settings.json 有 turn_gate 但无 recorder_feed → 报「未覆盖项目」清单**。即：框架已强制 turn_gate 接线，凡是被框架管到的项目，未装 recorder 会被机器点名。
- **诚实边界**：完全没装任何 hook 的项目在机制之外，无法录。覆盖承诺 = 「opt-in 项目的 100% session」+「缺口机器可查」，不是「全盘皆录」。

### 四、对 architecture 009 的实施前增量（第二批，与 Q45 增量合并并入）

1. §7 实测清单加第 6 项：CodeBuddy 是否支持用户级/全局 hooks（决定 per-project 还是全局覆盖）。
2. §3 daemon 增 `doctor` 子命令（机制 4）。
3. §3 watcher 职责补：`.turn` 普查 + 「有 state 无 trace」缺口事件（机制 3）。
4. §8 改动清单补：`check-standard`/`audit` 新增「turn_gate 已接线但 recorder 未接线」检查。
