## Q53 — 2026-10-24

**问题：**
你提到 `~/Library/Application Support/CodeBuddyExtension/Data/…/history/<会话>/<session>/index.json`——所以 CodeBuddy 本来就把 session 相关信息记录在那个文件夹里了？带我认认路：如果想看 session 里发生的一切（prompt、tool-call、hook、answer 等），都能在这个目录下找到吗？记入 questions。

**答案（基于实际侦查，实测时间 2026-10-24）：**

### 一、目录结构（实测确认）

```
~/Library/Application Support/CodeBuddyExtension/Data/<用户UUID>/CodeBuddyIDE/<用户UUID>/
  history/<会话集合ID>/<session_id>/        ← 每个会话一个文件夹
    index.json        ← 消息索引：{"messages":[{id, type, role: user|assistant|tool, isComplete}, …]}（按对话顺序）
    .index_bak.json   ← 索引备份
    messages/         ← ★ 正文：每条消息一个 <id>.json（本 session 实测 324 个）
    assets/           ← 附件（如用户贴的截图 image.*.png）
```

### 二、messages/<id>.json 的结构

外层 `{"role": "...", "message": "<内嵌 JSON 字符串>"}`，把内层字符串再 `json.loads` 一次得到真正内容：

| role | content 里有什么 |
|---|---|
| `user` | `type:"text"` 文本块 = **你的 prompt 原文**（前面会拼 `<user_info>`/`<rules>` 等注入上下文，真实提问在其中） |
| `assistant` | 两类块都有：`type:"text"` = **agent 的回答正文（markdown 全文）**；`type:"tool-call"` = **完整工具调用**（`toolName` + 全量 `args`，如 replace_in_file 的 filePath/old_str/new_str） |
| `tool` | 工具执行结果 |

### 三、所以「一切都在这里吗？」——分两半

| 内容 | 在 CodeBuddy 存储里？ | 在我们的 trace 里？ |
|---|---|---|
| prompt 原文 | ✅（user 消息，含注入上下文噪声） | ✅ |
| 工具调用（含全量 args） | ✅（assistant 的 tool-call 块） | ✅ |
| **回答正文** | ✅（assistant 的 text 块） | ❌（Q52 缺口 1） |
| **hook 触发/turn_gate 副作用/lifecycle** | ❌ 不在（这是管线事件，IDE 会话存储不管） | ✅（`hook`/`watcher`/`lifecycle`） |

**结论**：两个存储**互补**——CodeBuddy 目录 = 对话内容全量（含答案），我们的 trace = 管线事件（hook/副作用/版本溯源）。这同时把 Q52 缺口 1 的方案 B 变得更简单：**回答正文不用 watcher 追读，直接按 index 顺序读 `messages/` 即可**（读侧方案，待用户授权再做任何工具）。

### 四、阅读路引（今天就能用，无需任何工具）

1. 打开 `index.json` → 按顺序拿 `id` + `role`；
2. 对想看的那条，打开 `messages/<id>.json`；
3. 把外层 `message` 字段的字符串 `json.loads` 一次 → `content[]` 里 `type:"text"` 是文字（回答就在 assistant 的 text 块）、`type:"tool-call"` 是工具调用全参；
4. `Ctrl+F` 场景：想搜回答内容，直接在该 session 的 `messages/` 目录全局搜即可——**完整性由 index.json 的消息清单背书**（索引里有 id 的，正文文件必在）。

### 五、与其他记录的对应

`history/<集合>/<session>/` 的 `session_id` 与我们 trace 的 `session_id`、`.turn/{session}.json` 三者**同 ID**（如 cc41ed41287f45a8af8c392a5e721748）——三处可互相印证：CodeBuddy 存「说了什么/做了什么」，trace 存「管线怎么走」，`.turn` 存「网关记了什么账」。
