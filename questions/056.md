## Q56 — 2026-10-24

**问题：**
CodeBuddy 存储里会话（session）和会话集合是怎么组织的？比如同一个项目（如 ai_project_standard）的所有会话，是不是都在同一个集合文件夹下？

**答案（实测验证，2026-10-24）：**

**是——一个项目的所有会话都在同一个集合文件夹下。** 集合 = 工作区（项目），会话 = 一次对话线程。

### 一、两层结构 + 集合元数据

```
history/
  8e40bbcc63ebd428ff6f61d531045cc8/   ← 集合 = 工作区（本例= ai_project_standard）
    index.json     ← 会话目录：每条会话的标题/createdAt/lastMessageAt/chatMode/selectedModelId
    current.json   ← 当前活跃会话指针（实测 → cc41ed41…，含 lastUpdated）
    recent.json    ← 各会话最后活跃时间表
    cc41ed41287f45a8af8c392a5e721748/   ← 会话 = 一次对话线程
      index.json + messages/ + assets/
    （其余会话文件夹…）
  e155b4d9…/ 63 个会话                 ← 别的工作区（全局共 87 个集合）
```

### 二、实测证据

集合 `8e40bbcc` 下的会话与本项目的 9 个 trace session **逐一对应**；集合级 `index.json` 的标题全是本项目的对话（「新项目如何安装项目规范框架」「improvement_TOC 缺少一条的原因」…）。集合层三个元数据文件实测内容：

- `index.json`：`{"conversations":[{id, type:"craft", name, createdAt, lastMessageAt, chatMode, selectedModelId}…]}`
- `current.json`：`{"conversationId": "cc41ed…", "lastUpdated": …}`
- `recent.json`：`{<session_id>: <最后活跃时间>, …}`

### 三、粒度与分布

- **session = 一次对话线程**（可含多轮问答），不是一轮；同项目反复开会话全堆在同一集合（本集合 11 个会话文件夹，含 1 个空壳）。
- 全局 87 个集合，session 数分布 1~63 不等（最大 `e155b4d9…` 63 个）。
- 集合里多出的 `5a61e7ce` 不在我们 trace 的 9 个中——打开一看 `messages: 0`，又是 Q55 的「出生即空壳」模式（打开了没说话）。

### 四、意外收获（与 Q18 模型溯源相关）

集合 `index.json` 每条会话带 **`"selectedModelId": "hy3"`** ——CodeBuddy 自己记录的模型字段，属**平台元数据**而非 agent 自报。将来做 trace 的 `source.model` 权威打戳（Q52 缺口 2 相关），这里是比环境变量更硬的平台信号源。

### 五、分工总结

`history/<集合>/<会话>/` = 「哪个项目的哪次对话」（集合=项目，会话=线程）；我们 `session_trace/<plan>/<session>.jsonl` = 同构两层投影，记的是管线事件。另：会话的**可读标题**只在集合 index.json 里——找历史对话先看它。
