**答案（讨论）：**

**1. SKILL.md 哪里写了"任何改动都要进 history"？**
没有一句字面原话，但有等价的硬约束，分布三处：
- **Purpose（总原则）**："Every operation — including the full user prompt, the model that produced the result, and human-vs-AI authorship — is logged as one file per event under history/" —— 即"每一个操作都作为一条 event 记录到 history/ 下"。
- **When to use（触发清单）**前两条把"改动计划"列为必须记录的操作："Creating a new plan / architecture doc."（新建 plan / architecture 文档）、"Rewriting or extending an existing plan."（重写或扩展 → plan_modified）。
- **references/workflow.md §1 事件发射表**：把"Plan folder + architecture doc created"映射为 plan_created（前置 history_initialized）、"AI rewrites/extends the plan"映射为 plan_modified、"User asks a question during plan work → qna_recorded"。

结论：**有记录，只是不是口号式原话**，而是"every operation is logged"的总原则 + "新建/改写 architecture doc"明确列为触发项。

**2. 我为什么忘了？**
两个原因叠加：
- **把"登记索引"误当成"记录历史"**：建完 architecture/003.md 后我只把它登记进 architecture_index.json（latest_version 2→3），以为"已登记为目标版本"就是留痕。但 architecture_index 记的是"哪些版本存在/是否落地"，history 记的是"每次操作的完整溯源（谁、按什么 prompt、何时）"——职责不同，不能互相替代。
- **错误套用 plan_002 的"规划 vs 执行"分期**：参照 002 在规划期只写文件+登记索引、把 history 事件留到执行时，把 003 也当成"待执行计划"而延后记录；但 When to use 把"Creating a new plan / architecture doc"列为发生时就要记录的触发项，不该延后。
