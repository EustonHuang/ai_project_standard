## Q50 — 2026-10-24

**问题：**
教我怎么读这个 jsonl：结构是什么、这些信息都是什么意思？还有一旦有了回答（agent 的回答），怎么看到？请写进 questions。

**答案：**

### 一、文件在哪、长什么样

```
~/.ai_project_standard/session_trace/<项目名>/<session_id>.jsonl
```

每行一个 JSON 对象（JSONL），**append-only、按时间顺序**，一行 = 一个事件。直接用任何编辑器打开即可，或用命令行处理。

### 二、每行的结构（7 个字段）

```json
{"seq": 106, "ts": "2026-10-24T13:07:37.833+08:00", "kind": "prompt",
 "plan_id": "ai_project_standard", "session_id": "cc41ed…",
 "payload": { …事件的原始内容… }}
```

| 字段 | 含义 |
|---|---|
| `seq` | 本文件内单调递增序号（1 起），可当行号用 |
| `ts` | 事件时间（本地时区 ISO-8601） |
| `kind` | 事件类型（见下表）——**最重要** |
| `plan_id` / `session_id` | 属于哪个项目、哪个会话（路由键） |
| `payload` | 原始内容，**随 kind 不同** |

### 三、kind 速查表（payload 里有什么）

| kind | 什么时候产生 | payload 关键内容 |
|---|---|---|
| `prompt` | 你每次发消息 | **`prompt`：你的消息原文**；`transcript_path`（CodeBuddy 会话存储路径） |
| `tool_intent` | agent 每次即将调工具（PreToolUse） | `tool_name`、`tool_input`（含 filePath/old_str/new_str 等完整入参；被拦的尝试也在这） |
| `tool_call` | 工具执行完（PostToolUse） | `tool_name`、`tool_input`（文件写、skill、web、命令都算工具） |
| `turn_end` | agent 每轮答复结束 | Stop 事件 payload |
| `hook` | 每条 hook 触发的伴随标记 | `{hook, exit, ms}`——证明 hook 本身被录 |
| `watcher` | daemon 被动观察 | `turn_state`（turn_gate 的 .turn 状态）/ `coverage_gap` / `transcript_delta` |
| `lifecycle` | daemon 自身 | start/stop/spool 排水/异常 |
| `answer` / `reasoning` | agent 自发射（§6，**默认未开启**，见第五节） | 回答正文 / 推理摘要 |

### 四、一轮对话的典型序列

```
prompt(106) → hook(107) → [tool_intent(90) → hook → tool_call(92) → hook]×N
→ turn_end(104) → hook(105) → 下一条 prompt(106) …
```
即：**一轮 = 一条 prompt + 若干工具对 + 一条 turn_end**；`watcher turn_state` 穿插其间。

### 五、怎么读——4 条实用命令

```bash
T=~/.ai_project_standard/session_trace/ai_project_standard/cc41ed41287f45a8af8c392a5e721748.jsonl

# 1. 实时跟踪（新事件滚动打印）
tail -f "$T"

# 2. 只看你所有消息的原文+时间
python3 -c "
import json,os,sys
for l in open(os.path.expanduser(sys.argv[1])):
    r=json.loads(l)
    if r['kind']=='prompt': print(r['seq'], r['ts'][11:19], r['payload'].get('prompt','')[:100])
" "$T"

# 3. 看第 106 行完整内容（格式化）
sed -n '106p' "$T" | python3 -m json.tool

# 4. 列出所有工具调用（干了什么、改了哪个文件）
python3 -c "
import json,os,sys
for l in open(os.path.expanduser(sys.argv[1])):
    r=json.loads(l)
    if r['kind'] in ('tool_intent','tool_call'):
        ti=r['payload'].get('tool_input') or {}
        print(r['seq'], r['ts'][11:19], r['kind'], r['payload'].get('tool_name'), ti.get('filePath') or ti.get('file_path') or ti.get('command'))
" "$T"
```

### 六、一旦有了回答，怎么看到（诚实现状 + 两条开启路径）

**现状**：`kind=answer` 目前不会出现——hooks 只能拿到工具调用与 prompt，**agent 的回答正文不在默认捕获范围**（Q44 的「记录器自身管道之外」边界）。两条开启路径：

1. **自发射（§6，立刻可用）**：给项目加一条规则——agent 每轮结束执行
   `recorder_feed --kind answer --text "<最终回答全文>"`（可选再加 `--kind reasoning`）。
   之后查看：
   ```bash
   grep '"kind": "answer"' "$T" | tail -1 | python3 -c "import json,sys; print(json.loads(sys.stdin.read())['payload'])"
   ```
2. **transcript 追读（§7-4 已证实可行，待接线）**：payload 里已暴露 CodeBuddy 自己的会话 transcript 路径（`~/Library/Application Support/CodeBuddyExtension/Data/…/history/<会话>/<session>/index.json`）。把实际正文文件配进 `~/.ai_project_standard/config.json` 的 `transcript_path` 并重启 daemon，watcher 就会以 `transcript_delta` 事件追读增量（含回答文本）。注意 `index.json` 是索引，正文在旁路文件——接线前需先确认具体文件。

**今天就想看回答**：直接打开 payload 里 `transcript_path` 指向的 CodeBuddy 会话存储目录——那是 agent 回答的原始出处。
