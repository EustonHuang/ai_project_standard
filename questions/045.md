## Q45 — 2026-10-24

**问题（对 architecture 009 daemon 的两点精确化）：**
1. daemon 是 per-project 吗？还是一个进程监控所有项目？若 per-project，粒度是 per-session / per-answer / 还是别的？
2. daemon 的生命周期：怎么启动、怎么退出、中途失败或被杀怎么办、如何捕获并重新拉起？请记入 questions。

**答案：**

### 一、粒度：单 daemon per 用户，监控所有项目（非 per-project / per-session）

架构 009 §3 已定「单实例多项目」：**一个 daemon 服务本用户全部项目**，事件自带 `plan_id + session_id` 两键，daemon 据此路由落盘。粒度层级（由粗到细）：

| 层 | 粒度 | 说明 |
|---|---|---|
| daemon 进程 | **per 用户** | 一个进程；socket `~/.ai_project_standard/runtime/recorder.sock` 全局唯一。理由：降常驻成本、简化生命周期管理；trace 文件按 `(plan_slug, session_id)` 分文件互不干扰。 |
| trace 文件 | per (project, session) | `~/.ai_project_standard/session_trace/<plan_slug>/<session_id>.jsonl` |
| `seq` 序号 | per trace 文件 | 每文件内单调，daemon 断点恢复（扫文件尾） |

**per-session / per-answer 都不是进程粒度**：session 与 answer 只是 trace 里的记录单元（session_id 分文件；answer 是一行 `kind=answer` 事件）。进程不随 session 开关启停。

并发安全：多项目同时写 → daemon 单线程 accept + 逐行 append，天然串行；跨项目无共享 trace 文件，无锁竞争。

### 二、生命周期

**启动（三条路径，安装时确定主路径）：**
1. **launchd / LaunchAgent（推荐，保活）**：`install-session-recorder` 写 `~/Library/LaunchAgents/com.ai-project-standard.recorder.plist`，`RunAtLoad=true`、`KeepAlive=true` → 登录即拉起、崩了自动重启。Linux 等价 systemd user unit。
2. **首次 feeder 拉起（兜底）**：feeder connect 失败 → 临时 `spawn` daemon（`start --daemonize`，`setsid` 脱离会话）→ 重试连接 → 仍失败落 spool。保证「daemon 没跑时不丢事件」。
3. **手动**：`session_recorder.py start [--foreground]`。

**退出：**
- 优雅：`session_recorder.py stop` → SIGTERM → daemon 停 accept、排空 in-flight 事件、flush trace、删除 socket 文件、exit 0。
- 崩溃/被杀（SIGKILL）：无清理机会 → socket 文件残留。**捕获方式**：daemon 启动时对残留 socket 先 `connect` 探测——连得上=已有存活实例（幂等 exit 0）；连不上=死实例残留 → 删除重建。launchd `KeepAlive` 随后自动重启。
- 优雅关闭信号处理：SIGTERM/SIGINT → 排空 → 清理 → exit。

**失败/被杀的恢复链：**

| 阶段 | 机制 |
|---|---|
| 崩/杀瞬间 | feeder connect 失败 → **spool 兜底**（`spool/<ts>-<rand>.jsonl` 原子追加，静默 exit 0，P3：会话零影响） |
| 自动重拉 | launchd `KeepAlive=true` 重启；无 launchd 则下次 feeder 触发兜底拉起 |
| 重启后 | socket 残留探测（死实例清理）；**spool 排水**：按文件名时间序重放进对应 trace（时序保真，重排入 `lifecycle` 事件）后删除 |
| 数据完整性 | spool 保证「不丢」；trace 文件 append-only 保证「不坏」；崩时的半行 JSON 由 daemon 读侧跳过坏尾行（append-only + 按行校验） |

**kill -9 语义**：即「崩/被杀」路径；单点故障影响 = 重启后 spool 重放期间 trace 事件乱序以 spool 重放顺序为准（记录时序仍保真，因 spool 文件名含 ts）。不做分布式/多副本——单用户桌面场景单实例即可。
