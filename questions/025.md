## Q25 — 2026-10-05
**问题：** 安装项目规范之后，接下来在这个项目中正常 prompting 时，CodeBuddy IDE 能否保证把项目规范相关的 context 加载进 agent 上下文？用户怀疑当前的安装程度并不能保证这一点。

**答案（确认用户怀疑正确）：**

- **结论：不能保证。** 当前 `install` 无法保证 agent 在正常 prompt 时自动获得规范上下文。
- **根因分析**：
  - `install` 写入的 hook（`UserPromptSubmit→begin` / `PostToolUse→record` / `Stop→end`）只构成**强制门（enforcement scaffold）**，由 `turn_gate.py` 实现：在 `Stop` 时检查本回合是否动了 in-plan 文件却没有对应 `event_id > 基线` 且覆盖 `operation.target_files` 的历史事件，否则 `exit 2` 拦截。它**不注入任何规范文档内容到 context**。
  - CodeBuddy 每轮自动带入上下文的通道只有：① 编辑器打开文件/光标；② **Rules**（workspace/user rules）；③ **Skills**。而 `install` 三者均未配置：`copy_engine` 仅拷 `scripts/ references/ assets`（不拷 `skills/`），且**不写任何 Rule**（`.codebuddy/settings.json` 只有 hooks）。
  - 佐证：框架仓库本身在本会话中 agent 起初也不知道规范，是用户显式要求读 README 后才知——说明并非自动加载。
- **影响**：装完后 agent 是否照规范行事，完全取决于它"碰巧"是否读到文档。gate 能拦漏记（exit 2），但 agent 缺规范上下文时并不知道该跑 `append_history.py append` 补记，无法干净自恢复。
- **缺失的 must-do 修复**：`install` 还应额外写一条 **workspace Rule**（如 `.codebuddy/rules/` 或 settings 引用），声明本项目采用 ai_project_standard，凡改动受管文件前先读 `<project>/.plan-standard/README.md` 与 `references/workflow.md` 并按其记录。Rule 才是 CodeBuddy 可自动加载的载体，hook 不是。此缺口可立为 improvement。
