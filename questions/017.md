---

### 0. 先回答"有没有 hook"

**有，且不需要自己造。** CodeBuddy 提供 Hooks，官方明确"完全兼容 Claude Code Hooks 规范"，共 **7 种事件**（`SessionStart`、`SessionEnd`、`PreToolUse`、`PostToolUse`、`UserPromptSubmit`、**`Stop`**、`PreCompact`）。
- **`Stop` = "Agent 完成响应时触发"，正是"等 Agent 跑完所有东西之后再检查"**；退出码 **2** = 提供反馈，`stderr`/`stopReason` 注入下一条消息，即**可以强制 Agent 回头修正**，不是软提示。
- **`PostToolUse`**（matcher 按 `tool_name`）= 工具执行后触发，入参含 `tool_name`、`tool_input`（含 `filePath`）、`tool_response`——**正好用来捕获"本 agent 这一轮改了哪些文件"，无需扫描**。
- 配置位置：项目级 `<workspace>/.codebuddy/settings.json`（覆盖用户级 `~/.codebuddy/settings.json`）；脚本从 **stdin** 读 JSON、向 **stdout** 写 JSON；环境变量 `CODEBUDDY_PROJECT_DIR`。
- 退出码：`0` 放行 / `2` 阻止或反馈 / 其他 非阻塞警告。
- 出处：`https://www.codebuddy.cn/docs/ide/Features/Hooks`（Hook 功能使用文档）。

结论：**用 `UserPromptSubmit` 开轮 + `PostToolUse` 记账 + `Stop` 强检**，三个事件即可实现原设计意图，且天然满足"只查本轮、不扫全盘"。

### 第 1 层（修订）— SKILL.md 规则文案：堵死漏洞

**原错：** 开头说"任何"，举例却不加"等"，三条事件映射也不标"举例"，读起来像穷举 → 给自己留了钻空子的解释空间。

**修订后文案（写进 SKILL.md 并高亮）：**

> **MANDATORY — 任何改动都要进 history**
> 若本回合在 plan 文件夹内创建/修改/删除了**任何文件（包含但不仅限于 `architecture/*.md`、`*_index.json`、`*_TOC.md`、`questions/*`、`issues/*`、`SKILL.md`、`references/*`、`scripts/*`、`assets/*`、`.codebuddy/settings.json` 等——本清单为举例、非穷举，凡属该 plan 的文件一律适用）**，则**必须**在同一回合追加对应 history 事件。
> 事件类型映射**仅为举例、非穷举**（按实际语义选择，不确定时用 `plan_modified` 并在 `comments` 说明）：
> - 例如：新建/改写 architecture 文档、改动任何索引 → `plan_modified`
> - 例如：用户提问 → `qna_recorded`（且 `questions/` 与 history **双录**）
> - 例如：发现既有记录错漏 → `correction`（引用 `corrects_event_id`）
> - 例如：删除文件、改动脚本/文档 → 同样按语义归入 `plan_modified` 等
> **不存在"因为是生成物/因为是索引/因为待执行就先不记"的豁免。** 判断标准只有一条：**本回合是否动了该 plan 的文件**。

要点：**两处清单都明确标注"包含但不仅限于……等""仅为举例、非穷举"**，堵住"清单里没写就不算"的漏洞。

### 第 2 层（修订）— 用 hook 实现**本轮作用域**强检，**废弃全盘扫描**

**Q16 §2 的"全目录 mtime 扫描"方案作废**，理由正如质疑：① 规模不可扩展；② 并发下会把别人的改动算到我头上（误报），也会因别人追加了事件而误判我已记录（漏报）。

**新方案：turn-scoped（本轮作用域）+ hook 驱动，永不扫全盘。**

三个 hook，各自只做 O(1)~O(本轮改动数) 的事：

| 事件 | 作用 | 脚本子命令 | 成本 |
|---|---|---|---|
| `UserPromptSubmit` | **开轮**：记 `baseline_max_id = history_index.max_id`，清空 `declared[]` | `begin` | 读 1 个索引 |
| `PostToolUse`（matcher: `write_to_file\|replace_in_file\|delete_file\|Write\|Edit`） | **记账**：把本工具刚写的 `filePath` 追加进 `declared[]`（去重） | `record` | 追加 1 行 |
| `Stop` | **强检**：本轮 `declared[]` 非空时，必须存在 `event_id > baseline_max_id` 的新事件，且其 `operation.target_files` **覆盖** `declared[]` | `end` | 读索引 + 只读本轮新增的 0~3 个事件文件 |

**判定与后果（Stop）：**
- `declared[]` 为空 → `exit 0`，放行。
- `declared[]` 非空且被本轮新事件覆盖 → `exit 0`。
- `declared[]` 非空但**未被覆盖** → 输出 `{"continue": false, "stopReason": "本回合修改了 X、Y，但未追加 history 事件（或 target_files 未覆盖），请先 append 再结束回合"}`，**`exit 2`** → 反馈注入下一条消息，**Agent 被迫回头补记**，补完 Stop 再触发一次即通过。

**为什么满足两个硬要求：**
- **不扫全盘、可扩展**：全程不遍历目录。只读写 `.turn/<session_id>.json`（本轮清单，通常几行）+ `history_index.json` + 本轮新增的少数事件文件。成本 = O(本轮改动数)，**与 history/questions 的历史总量无关**，`questions/` 涨到一万个文件也不变慢。
- **并发正确**：清单按 `session_id` 隔离，别的 agent 的改动**根本不会进入我的 `declared[]`**（不误报）；判定要求"覆盖我的 `declared[]` 的事件 `event_id > baseline_max_id`"，别人追加的事件若不含我的文件就**不算覆盖**（不漏报）。

**归属 plan 的判定（也不扫全盘）：** 对 `declared[]` 中每个文件，向上逐级查找含 `history_index.json` 的祖先目录作为 plan 根——O(目录深度)，不是全盘扫描。不在任何 plan 内的文件直接忽略。

**配置示例（`<workspace>/.codebuddy/settings.json`）：**
```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command",
        "command": "python3 \"$CODEBUDDY_PROJECT_DIR/.codebuddy/skills/plan-history-recorder/scripts/turn_gate.py\" begin",
        "timeout": 10 } ] }
    ],
    "PostToolUse": [
      { "matcher": "write_to_file|replace_in_file|delete_file|Write|Edit",
        "hooks": [ { "type": "command",
          "command": "python3 \"$CODEBUDDY_PROJECT_DIR/.codebuddy/skills/plan-history-recorder/scripts/turn_gate.py\" record",
          "timeout": 10 } ] }
    ],
    "Stop": [
      { "hooks": [ { "type": "command",
        "command": "python3 \"$CODEBUDDY_PROJECT_DIR/.codebuddy/skills/plan-history-recorder/scripts/turn_gate.py\" end",
        "timeout": 15 } ] }
    ]
  }
}
```

**已知边界（诚实列出）：** `execute_command`/`Bash` 改了哪些文件无法从 hook 入参可靠推断 → 采取"尽力而为 + 兜底声明"：命令串中若出现 plan 内路径则记账；否则不记账，此时依赖第 1 层规则（agent 主动 append）。这是 hook 机制本身的边界，不是设计偷懒。
