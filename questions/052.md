## Q52 — 2026-10-24

**问题（实际使用暴露的两个缺口）：**
1. turn 的 trace 里有 prompt/工具调用/turn_end，但 **agent 的回答本身完全没录**——回答里的文字、bash 命令、JSON 块全都不在。这可能抓到吗？
2. trace 每行**没有版本戳**——升级之后（v0.10/v1.0）看不出每行是哪个引擎版本记的。项目标准的 history 事件都有 `standard_version` 快照，trace 应该同构。请记入 questions。

**答案（分析 + 候选方案，均未实施——等用户选定并授权后才动手）：**

### 一、回答正文没录（确认是真缺口）

Q51 的生命周期里 `prompt`/`tool_intent`/`tool_call`/`turn_end` 都有，唯独没有回答正文——因为回答既不是工具调用也不是 hook 事件（Q44/Q50 已述边界）。可行路径：

| 方案 | 做法 | 优 | 劣 |
|---|---|---|---|
| **A. §6 自发射** | 项目规则（或用户规则）要求 agent 每轮结束跑 `recorder_feed --kind answer --text "<回答全文>"`（可选 `--kind reasoning`） | 立刻可用；内容即最终 markdown，含命令/代码块；精确 | 依赖 agent 合规（须进规则）；每轮多一次工具调用 |
| **B. transcript 追读（推荐方向）** | hook payload 已实测暴露 `transcript_path`（`~/Library/Application Support/CodeBuddyExtension/Data/…/history/<会话>/<session>/index.json`，Q47 §7-4）。先侦查 index 旁的**正文文件**格式，再把实际正文配进 `~/.ai_project_standard/config.json` 的 `transcript_path`，watcher 追读增量 → `transcript_delta` 事件自动入 trace | 全自动、零 agent 合作；连用户在 IDE 里的动作也可能覆盖 | `index.json` 是索引非正文，须先侦查旁路文件；delta 是原始文本，可能含中间态，需要定位解析 |
| **A+B 组合** | B 自动兜底 + A 精确存最终版 | 覆盖最全 | 两处可能有重复内容 |

对齐问题：回答块与工具调用的时间线靠 `ts` 对齐（同一 turn 窗口内按序排列）。

### 二、trace 行缺版本戳（确认是真缺口）

history 事件有 `standard_version` 快照（architecture 006 IMP-003：记录时锁文件值的快照、写后不变、禁止手填）；trace 行应同构，否则升级后无法回答「这行是谁记的、当时什么版本」。

**候选方案**：trace 行 schema 增加一个 `standard_version` 字段——
- 取值：事件产生时读 `<plan_root>/standard_version` 锁文件（feeder 已有 `CODEBUDDY_PROJECT_DIR`，读锁文件零依赖）；
- 语义：**记录时快照**（与 history 同构：写后不变；查旧行即知当时版本）；
- 实现位置二选一：feeder 层打（事件自包含、daemon 不用管；推荐）或 daemon 按 plan_id 缓存读取；
- 兼容：trace append-only，旧行不回填即可（新行起带字段）；不涉及 schema_version bump（trace 无 schema_version 机制）。
