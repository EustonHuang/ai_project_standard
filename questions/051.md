## Q51 — 2026-10-24

**问题：**
我看出模式了：一个回答以 `kind=prompt` 开始、以 `hook`+`name=turn_end` 结束——我理解得对吗？请从 cc41….jsonl 抓一个从 prompt 到 turn_end 的完整生命周期实例，解释发生了什么。记入 questions。

**答案：**

**你的理解基本正确**：一个 turn（= 你的一条消息 + agent 的一次完整应答）确实从 `kind=prompt` 开始、以 `turn_end` 收尾；你看到「结尾是 hook 且 name=turn_end」是因为**每条 hook 源事件都带一条 `hook` 伴随行**，所以视觉上最后两行是 `turn_end` + `hook(turn_end)`——伴随行是噪音，可忽略。

### 一、真实实例（seq 215–218，本轮之前的那次纯问答 turn）

```
215 13:27:14.940 prompt   你: {"kind": "prompt", "ts": "2026-10-24T11:54:51.833…（你粘贴 JSON 行提问）
216 13:27:14.942 hook     (伴随: prompt)                 ← UserPromptSubmit hook 触发过的标记
217 13:27:15.260 watcher  turn_state (.turn 变化)         ← turn_gate begin 更新了 .turn 状态（副作用）
218 13:27:24.267 turn_end {'hook_event_name': 'Stop', …}  ← Stop hook：agent 本轮应答结束
```

逐行解释：
1. **215 `prompt`**：你在 CodeBuddy 按下回车 → IDE 触发 `UserPromptSubmit` hook → feeder 把你的消息原文（`payload.prompt`）推给 daemon。
2. **216 `hook(prompt)`**：daemon 对这次 hook 触发的伴随标记（`{hook:"prompt", exit:0}`），证明 hook 本身被录（P4）。
3. **217 `watcher turn_state`**：turn_gate 的 `begin` 写了 `.turn/{session}.json` → daemon 的 watcher 1 秒内观察到文件变化 → 记下（hook 副作用 ground truth）。
4. **218 `turn_end`**：我答完、本轮结束 → IDE 触发 `Stop` hook → `payload` 带 `hook_event_name:"Stop"`。其后再跟一条 `hook(turn_end)` 伴随行。

### 二、含工具调用的 turn 长什么样

若我那轮动了文件，中间会插入**成对**的：
```
tool_intent(PreToolUse) → hook → tool_call(PostToolUse) → hook    ← 每次工具调用一组
watcher turn_state                                                ← turn_gate 记账副作用，穿插出现
```
`tool_intent` 是「即将执行」、`tool_call` 是「执行完毕」，payload 里 `tool_name` + `tool_input`（含目标文件/命令）。

### 三、模式总结

```
一个 turn = prompt + [hook 伴随] + { N × (tool_intent + hook + tool_call + hook) } + watcher* + turn_end + [hook 伴随]
```
- 一个 turn 的时间窗 = `Stop` 与上一个 `Stop` 之间；无工具调用的纯问答 turn 只有 4 行（如上例）。
- 过滤口诀：**看真消息只认 `payload.hook_event_name`**（UserPromptSubmit / Stop），`hook`/`watcher`/`lifecycle` 是辅助行。
- 注：最后一个 turn 的 `turn_end` 要等我答完才出现，所以「最后一条 prompt 之后没有 turn_end」是正常现象。
