## Q54 — 2026-10-24

**问题：**
我想看**本 session** 的内容——帮我找到这个 session 的 uuid，并在 CodeBuddy 存储里带路：怎么一步步拿到信息？

**答案（实测走通，本 session 实例）：**

### 一、本 session 的实际路径与三个 ID

```
~/Library/Application Support/CodeBuddyExtension/Data/
  ef38475c-d6ec-4147-8c60-dca70502e0b3/        ← ① 工作区/数据 UUID
    CodeBuddyIDE/
      ef38475c-d6ec-4147-8c60-dca70502e0b3/    ← ② IDE 实例 UUID（本机与①同值）
        history/
          8e40bbcc63ebd428ff6f61d531045cc8/    ← ③ 会话集合 ID（工作区下的会话分组）
            cc41ed41287f45a8af8c392a5e721748/  ← ④ session_id（与我们 trace、.turn 同 ID）
              index.json  messages/  assets/  .index_bak.json
```

**怎么自己找到④**（别用裸 `find -name <sid>`——`plan-task/` 下存在同名目录，那是任务存储不是对话，会撞车）：

```bash
SID=cc41ed41287f45a8af8c392a5e721748
find "$HOME/Library/Application Support/CodeBuddyExtension/Data" \
     -type d -path "*history/*/$SID"
```

### 二、读取流程（index → messages，两次 json.loads）

```python
import json, os
d = "<上面 find 到的目录>"
idx = json.load(open(os.path.join(d, "index.json")))["messages"]   # 按对话顺序
for m in idx:                                   # role: user|assistant|tool
    f = os.path.join(d, "messages", m["id"] + ".json")
    inner = json.loads(json.load(open(f))["message"])   # 外层是字符串，再解析一次
    for c in inner["content"]:
        if c["type"] == "text":       print(c["text"])          # 提问原文 / 回答全文
        elif c["type"] == "tool-call": print(c["toolName"], c["args"])  # 工具调用全参
```

实测本 session：index 共 **338 条消息**（持续增长）；最后一条 user 消息的正文尾部是 `…<user_query> let's say I want to see this session's content…`；最后一条 assistant 的 text 块正是我上一轮的回答开头。

### 三、三个坑（实测踩过）

1. **真实提问包在 `<user_query>` 标签里**：user 消息正文 = 注入上下文（`<user_info>`/`<rules>`/`<agent_requestable_workspace_rules>` 等）+ `<user_query>你的问题</user_query>`。搜自己的话要搜 `<user_query>` 之后的部分。
2. **`isComplete` 对 assistant 不可信**：老 assistant 消息也显示 `false`（可能只有 user/tool 会置 true），别拿它判断「是否已答完」；判断回合结束用我们 trace 的 `turn_end` 更可靠。
3. **同名目录陷阱**：`plan-task/<集合>/<session>/` 与 `history/<集合>/<session>/` 同 session_id 并存，`find -name` 会撞到前者（无 index.json 会报错），务必加 `-path "*history/*"`。

### 四、与 trace 的分工（回顾）

- 看**对话内容**（你说了什么、我答了什么、每次工具调用的全参）→ 本目录（index+messages）。
- 看**管线事件**（hook 触发、turn_gate 副作用、lifecycle）→ `~/.ai_project_standard/session_trace/…`。
- 两者 session_id 相同，可互相定位：trace 里看到感兴趣的时间点 → 来 messages/ 按顺序找那条前后的消息。
