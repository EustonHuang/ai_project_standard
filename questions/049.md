## Q49 — 2026-10-24

**问题：**
你说更新 v0.9 各项目才有 python 脚本和 install-session-recorder，但架构里又说 tracing 不分项目/session、只开一个 daemon 就能 trace 所有 session——这两者矛盾吗？

**答案：**

不矛盾，是**两层**被混成了一层：

1. **产生事件的一层是 per-project 的（水龙头）**：每个项目要有引擎脚本 + 接好四条 hooks，它的 session 才会**发出**事件。未装的项目不产生任何事件，daemon 无从得知它存在。
2. **收集事件的一层是 per-user 全局的（收集器）**：daemon 只有一个（Q45），接收**所有已装龙头项目**推来的事件。「一个 daemon trace 所有 session」说的是收集端共享，不是「能看见未装项目」。

且 **session 在落盘层是分开的**：一个 daemon 往多个 trace 文件写，每个 `(plan_id, session_id)` 一个文件——共享的是进程，不共享文件。

合并表述：**更新 v0.9 + 跑 skill = 给该项目装龙头；所有装了龙头的项目的全部 session，由同一个 daemon 收进各自独立的 trace 文件；未装项目不在收集范围。**

唯一实现「一次安装覆盖全部项目」的路径是**用户级全局 hooks**（architecture 009 §7 第 6 项待实测）：若 CodeBuddy 支持，feeder 只挂用户级配置，才真正是一个安装、全项目被录。目前未证实，默认 per-project 接线。
