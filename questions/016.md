**答案（讨论，方案已提出，脚本/SKILL.md 改动待执行）：**

**方案总称：Turn-end history gate（收尾强制门）——三层叠加。**

**第 1 层 — agent 行为规则（写进 SKILL.md 并高亮）**
- 规则：若本回合在 plan 文件夹内创建/修改/删除了**任何** plan 文件（`architecture/*.md`、`*_index.json`、`*_TOC.md`、`questions/*`、`issues/*`、`SKILL.md`、`references/*`），则**必须**在同一回合追加对应 history 事件：
  - 新建/改写 architecture 文档、改动索引 → `plan_modified`
  - 用户提问 → `qna_recorded`（且 questions/ 与 history 双录）
  - 发现错漏 → `correction`
- 收尾前**必须**运行机械校验：`python scripts/append_history.py gate --plan <plan>`
  - exit 0 → 允许结束回合。
  - exit 1 → 打印 `UNLOGGED CHANGES` 清单，**回合视为未完成**，必须补追加 history 事件后重跑 gate，直到通过。
- 明示禁止的豁免理由：不得因"只是登记了 `architecture_index`""这是待执行计划、执行时再补""只是生成物（TOC）"而跳过——这正是 Q15 那次漏记的实际托辞。

**第 2 层 — 脚本机械兜底（新增 `gate` 子命令）**
- 取 `history_index.json` 中最新事件的 `recorded_at` 作为 `last_event_time`（无任何事件则视为 0）。
- 扫描**受管文件**：`architecture/*.md`、`architecture_index.json`、`architecture_TOC.md`、`questions/*.md`、`questions_index.json`、`questions_TOC.md`、`issues/*/description.json`、`issues_index.json`、`issues_TOC.md`、根级 plan 文档（`SKILL.md`、`references/*.md`）。
- **排除**历史机制自身与运行时产物：`history/*`、`history_index.json`、`history_TOC.md`、`.lock/`、`*.tmp`、`__pycache__`、`.DS_Store`。
- 判据：任一受管文件 `mtime > last_event_time` → 判为"未记录的改动"，列出并 `exit 1`；否则 `exit 0` 打印 `GATE OK`。
- 判据正确性：history 事件在改动**之后**追加，故追加后 `last_event_time` 必然新于所有受管文件 → 通过；只改了文件却没追加事件 → 必然被抓。Q15 的漏记情形（改 `architecture/003.md` + `architecture_index.json` 但无新事件）正好会被拦下。

**第 3 层 — 流程文档 + 事后审计**
- `references/workflow.md` §6 校验清单增加"收尾门"步骤；§7 明确提问要双录（`questions/` + `qna_recorded`）。
- `audit` 把 gate 结果作为 NOTE 输出（非致命），便于事后发现漏记。

**为什么必须叠加三层：** 第 1 层管 agent 行为（靠 SKILL.md 高亮提醒 + 自觉），第 2 层管机械校验（不靠自觉、靠脚本），第 3 层管流程文档与事后审计。任一层单独都可能失效（本次即是第 1 层失守），叠加才不漏。

**漏记的补正方式：** 仍是**追加新事件**（补记 `plan_modified`，必要时 `correction` 引用 `corrects_event_id`），符合只增不改，绝不 in-place 修改已有事件。
