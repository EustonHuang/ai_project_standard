## Q40 — 2026-10-23

**问题（对 Q39 的纠正）：**
不要在当前框架（ai-project-standard）下讨论「能不能」。我知道它做不到。我要的是**怎么把它做成**——把 CodeBuddy session 里的一切（用户 prompt、agent 回答、thinking、skill、写的文件、web search、hook、输出）全录下来的**方法**。

**答案：**

核心思路：**不要塞进 ai-project-standard 的 `history/` schema**（那是轻量溯源，故意不存全文）。另建一个**独立的、hook 驱动的会话记录器（session recorder）**，把每个 CodeBuddy hook 事件追加进 per-session 的 JSONL trace。这就是实现方法。

### 一、架构

一个记录脚本（如 `session_recorder.py`）+ hook 配置，把每个 hook 事件 append 到 `session_trace/{session_id}.jsonl`，每行 = `{event, ts, payload}`。接线模式复用 `turn_gate.py` 已有的那套（`.codebuddy/settings.json` 里挂命令），但它**只记录不拦截**。

### 二、每个 hook 捕什么（整套机制的关键）

- `UserPromptSubmit → capture`：payload 含 prompt 文本 → **逐字录下用户输入**。
- `PostToolUse → capture`：记录每个工具调用的 `{tool, input, output}`。文件写、skill 调用、web search、web fetch、execute_command 都是工具调用 → **一个钩子自动覆盖 skill / 写文件 / web / 命令 / agent 做的一切**。
- `PreToolUse → capture`（可选）：执行前记意图，连被拦/失败的尝试也留痕。
- `Stop → capture`：标记本轮结束。
- `SessionStart` / `SubagentStop` / `PreCompact`：会话生命周期。

### 三、两个真正难点怎么补

1. **agent 最终回答正文（不是工具调用）：**
   - (a) 在 `Stop` 时拷贝 CodeBuddy 自己的会话 transcript 文件（最完整，含真实助手消息）；定位 CodeBuddy 持久化会话的位置，把最新一轮追加进 trace。
   - (b) agent 自发射：用一条 rule 强制 agent 在每轮结束把回答正文 append 进 trace。可靠、agent 协作式。
2. **thinking（思考）：** 原始隐藏推理仅当平台暴露才可捕。做法：先实测 hook payload 有无 reasoning 字段，有则直采；没有则用 rule 强制 agent 边做边发结构化 `reasoning` 条目，捕获的是**陈述式推理**（审计通常用这个就够），非原始隐藏 CoT。

### 四、存储与和 history 的衔接

JSONL trace 本身即「输入输出全录」有序记录。为避免撑爆溯源历史，让 `history/` 事件**引用** trace 路径，而非内嵌逐字正文。

### 五、前提（必须实测，不能假设）

确认每个 CodeBuddy hook payload 实际携带什么：UserPromptSubmit 是否含 prompt 文本？PostToolUse 是否含 tool output？有无 reasoning 字段？框架 README 已提醒「hook 执行未写入 CodeBuddy 公开文档——须实测验证」。该验证是第 0 步。

**结论：** prompt + 工具调用 + 文件 + skill + web + 输出 今天即可经 hook 全捕；唯一受平台透明度限制的是原始隐藏推理，其余都可行。本记录器与 history 框架解耦，是新做的独立 hook 包（可落地为 `skills/session-recorder`）。
